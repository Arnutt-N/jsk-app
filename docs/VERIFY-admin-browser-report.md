## สรุปผู้บริหาร (ภาษาบ้านๆ)

ตรวจข้อสำคัญ (P1) ทั้ง 8 ข้อของรายงาน audit ด้วยการอ่านโค้ดจริงแล้ว ผลคือ **พังจริง 7 ข้อครึ่ง** — มีข้อเดียวที่รายงานเข้าใจผิดครึ่งหนึ่ง (เรื่องเตือนหมดเวลาในหน้าตอบแชท จริงๆ หน้านั้นไม่มีเตือนเลย ไม่ใช่เตือนผิดที่)

ตาราง: พังจริง 7 ข้อ · ไม่พัง 0 ข้อ · รายงานคลาดเคลื่อนบางส่วน 1 ข้อ (A11Y-02 ครึ่งหลัง) · ต้องลองกดใน browser เพิ่มทุกข้อ (เพื่อถ่ายคลิป/ภาพเป็นหลักฐานสุดท้าย)

คำที่อธิบายครั้งแรก:
- **Escape** = ปุ่มหนีบนคีย์บอร์ด กดแล้วหน้าต่างควรปิด
- **Tab** = ปุ่มเลื่อนช่องบนคีย์บอร์ด ใช้แทนเมาส์
- **โปรแกรมอ่านจอ** = โปรแกรมช่วยอ่านหน้าจอให้คนมองไม่เห็นฟัง
- **ตัวยกเลิกคำขอเก่า** = กลไกทิ้งคำตอบที่มาช้า (AbortController/เลขลำดับคำขอ) ไม่ให้ทับคำตอบล่าสุด

## สิ่งที่ยังไม่ได้ทำ (ต้องกดใน browser จริง)

ทีมตรวจยืนยันจากโค้ดแล้ว แต่ขั้นตอน browser (เปิดจอจริง ถ่ายภาพ/คลิป) ยังไม่ได้รัน เพราะต้องมีเซิร์ฟเวอร์ + บัญชีทดสอบ สคริปต์เปล่ารออยู่ที่ `frontend/e2e/admin-audit-verify/` ขั้นตอนต่อข้ออยู่ใน `docs/PRP-admin-browser-verification.md` Task 2–5

รายการ browser ที่ค้าง:
1. NAV-01: เปิดจอมือถือ 360px พิมพ์ค้นหา ถ่ายว่าไม่มีผล
2. NAV-02: ล็อกอินเป็น AGENT กดเมนูนัดหมาย ดู URL เด้งกลับ
3. SAFE-02/03: เน็ตช้า (throttle) กด Escape/คลิกพื้นหลัง/กดลบเบิ้ล นับคำสั่งที่ออกไป
4. A11Y-01: จอมือถือกด Tab รัว ดูว่าโฟกัสหลุดหลังฉากไหม
5. NET-01: พิมพ์ค้นหารัว + เน็ตช้า ดูว่าผลตรงคำค้นล่าสุดไหม
6. ตาราง matrix 49 เส้นทาง: เติมช่อง role/viewport/keyboard/touch ให้ครบ

## แนะนำขั้นต่อไป

ซ่อมได้เลย 7 ข้อที่พังจริงตามโค้ด ไม่ต้องรอ browser (browser เป็นแค่หลักฐานประกอบ) ลำดับเดียวกับที่ audit แนะนำ: ค้นหา+สิทธิ์เมนู → ออกจากระบบ+กันกดซ้ำ → ลิ้นชัก/เตือนหมดเวลา → ผลค้นหาเก่าทับใหม่ ส่วน A11Y-02 ครึ่งหลัง (live-chat ไม่มีเตือน) ให้เจ้าของระบบยืนยันว่าตั้งใจตัดออกหรือไม่ก่อนซ่อม

## Iron rule (user-mandated 2026-10-13)

งานนี้ไม่มี key/secret/token ใดๆ พิมพ์ในแชต สรุป หรือ log ตรวจโดยการนับไฟล์เท่านั้น
