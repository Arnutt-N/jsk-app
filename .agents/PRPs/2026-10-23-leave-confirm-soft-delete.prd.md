# PRD: รวมปุ่มปิด LIFF + นโยบายลบแบบซ่อน (2026-10-23)

## คำตัดสินผู้ใช้ (ล็อกแล้ว 2026-10-23)
1. **ปุ่มปิด/ย้อนกลับ = ถามก่อนปิด (แบบหน้าจอง)** — กดยกเลิกระหว่างกรอกฟอร์มต้องมีหน้าต่างถามยืนยันก่อน 1 ครั้ง แล้วค่อยปิด ใช้เหมือนกันทุกหน้าฟอร์มใน LINE
2. **ลบข้อมูล = ซ่อนไว้ก่อน กู้ได้** — ปุ่มลบหลังบ้าน = ปิดสวิตช์ซ่อนไว้ (ของจริงยังอยู่ กู้คืนได้) ห้ามลบถาวร

## ปัญหา
- **ปุ่มปิด 3 แบบปนกัน:** หน้าจอง (`booking`) กับไกล่เกลี่ยหนี้ (`debt-mediation`) กับยื่นคำร้อง (`service-request`) กดยกเลิกแล้วถามก่อน (ใช้ `useLiffLeave`) แต่หน้ายื่นคำร้องเดี่ยว (`service-request-single`) กับฟอร์มรุ่น 2 (`request-v2`) กดยกเลิกแล้วปิดเลยไม่ถาม (ใช้ `handleClose` ตรง) ส่วนจอสำเร็จของ `booking` ปิดตรงแบบไม่มีแผนสำรองนอก LINE
- **ปุ่มลบเสี่ยงของหาย:** `DELETE auto-replies` ลบแถวจริง (`db.delete`), `DELETE intents categories/keywords/responses` ลบจริง, `DELETE taxonomy categories/topics` ลบจริง — ขัดกับนโยบาย "ซ่อนไว้ก่อน" ทั้งที่ตารางมีคอลัมน์ `is_active` พร้อมแล้ว และหน้าจอ taxonomy ยังเขียนว่า "จะถูกลบถาวร"

## ขอบเขต

### A. ปุ่มปิด LIFF — ทำทุกฟอร์มให้เหมือนหน้าจอง (`useLiffLeave`)
| หน้า | ทำอะไร |
|---|---|
| `service-request-single` | ปุ่ม "ยกเลิก" เปลี่ยนจากปิดทันที → ถามก่อนด้วย `useLiffLeave` (เพิ่ม dialog ยืนยันแบบ `service-request`) |
| `request-v2` | ไม่แตะ — ตรวจแล้วไม่มีปุ่มออกกลางฟอร์มเลย (มีแค่ปุ่มปิดจอสำเร็จ) การเพิ่มปุ่มคือ UI ใหม่ บันทึกเป็น follow-up |
| `service-request`, `debt-mediation`, `booking` (ตัวช่วย wizard) | ไม่แตะ — ถามก่อนอยู่แล้ว (ตรวจอย่างเดียว) |
| จอสำเร็จทุกหน้า ("บันทึกสำเร็จ" + นับถอยหลังปิดเอง) | ไม่แตะ — ข้อมูลบันทึกแล้ว ถามซ้ำกวนผู้ใช้ ปิดตรงคงเดิม |
| `booking` จอสำเร็จ (`page.tsx:650`) | เติมแผนสำรองนอก LINE (`window.close` → ลิงก์ LINE) อย่างเดียว ไม่เปลี่ยนพฤติกรรมใน LINE |
| `close-test` | ไม่แตะ — หน้าไว้ทดสอบช่าง |

### B. ลบ = ซ่อน (`is_active=False`) — ไม่เปลี่ยนโครงสร้างฐานข้อมูล
| เส้นทางหลังบ้าน | ทำอะไร |
|---|---|
| `DELETE /admin/auto-replies/{id}` | จากลบแถวจริง → ตั้ง `is_active=False` (ตารางมีคอลัมน์แล้ว) |
| `DELETE /admin/intents/categories/{id}` | จากลบแถวจริง → ตั้ง `is_active=False` (ตารางมีคอลัมน์แล้ว) |
| `DELETE /admin/taxonomy/categories/{id}` + `/topics/{id}` | จากลบแถวจริง → ตั้ง `is_active=False` (ที่อ่านข้อมูลกรอง `is_active` อยู่แล้ว) |
| `DELETE /admin/intents/keywords/{id}` + `/responses/{id}` | ไม่แตะ — รายการย่อยในหมวด (คีย์เวิร์ดไม่มีคอลัมน์ซ่อน) ปุ่มเปิด/ปิดระดับหมวดคุมอยู่แล้ว |
| `DELETE /admin/canned-responses/{id}` | ไม่แตะ — ซ่อนอยู่แล้ว (ตรวจอย่างเดียว) |
| กฎกันหมวดที่มีหัวข้อย่อย (`taxonomy`: มี topics ห้ามลบ) | คงเดิม — ห้ามทั้งลบและซ่อนจนกว่าย้ายหัวข้อออกก่อน |

### C. คำบนหน้าจอ — พูดให้ตรงความจริง

- หน้าต่างยืนยันลบ taxonomy: "จะถูกลบถาวร" → "จะถูกซ่อนไว้ กู้คืนได้" ปุ่ม "ลบ" → "ปิดใช้งาน"
- ข้อความแจ้งผล: "ลบแล้ว" → "ปิดใช้งานแล้ว (กู้คืนได้)"

## ไม่ทำ

- ไม่เปลี่ยนโครงสร้างฐานข้อมูล (migration) — คอลัมน์มีครบแล้ว
- ไม่แตะจอสำเร็จที่ปิดตรง (ข้อมูลบันทึกแล้ว)
- ไม่แตะหน้า `close-test` (ของช่าง)
- ไม่เปลี่ยนพฤติกรรมตัวกรอง/ค้นหาใด ๆ

## เกณฑ์ผ่าน

- กดยกเลิกกลางฟอร์มทุกหน้า LIFF → มีหน้าต่างถามก่อน 1 ครั้งเสมอ
- เรียก DELETE ทุกเส้นทางในขอบเขต → แถวยังอยู่ แต่ `is_active=False` และไม่โผล่ในรายการที่ผู้ใช้เห็น
- เปิดกลับด้วย PUT/PATCH `is_active=True` ได้ (กู้คืนได้จริง)
- `tsc` ผ่าน, เทสต์ชุดที่แตะต้องเขียว, CI เขียวบน PR
- ลองกดจริงบนมือถือ: ยกเลิกกลางฟอร์ม → ถามก่อน; ปิด/ซ่อนหลังบ้าน → กู้กลับได้
