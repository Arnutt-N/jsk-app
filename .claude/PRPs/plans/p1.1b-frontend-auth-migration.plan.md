# Plan: P1.1b Frontend Auth Migration (PR 2B)

## Summary
Migrate the admin frontend from Bearer+localStorage auth to HttpOnly cookie
auth: credentialed requests, in-memory CSRF double-submit, server-side session
bootstrap via `/auth/me`, single-flight cookie refresh, one-time Bearer→cookie
migration, ticket-based WebSocket auth, and multi-tab logout sync — all gated
behind `NEXT_PUBLIC_COOKIE_AUTH` (default off = byte-identical to today).

## User Story
As an admin-console operator, I want my session credentials kept in HttpOnly
cookies (not JavaScript-readable localStorage) and my refresh tokens rotated
server-side, so that an XSS cannot exfiltrate long-lived credentials and a
stolen refresh token is detected + revoked.

## Problem → Solution
localStorage tokens + token-presence-inferred auth + no CSRF + JWT-over-WS →
cookie auth with server bootstrap, in-memory CSRF, single-flight rotation, and
single-use WS tickets (gated by a flag for safe dark rollout).

## Task 1: CSRF store (`frontend/lib/csrfStore.ts`) — NEW FILE
- **ACTION**: Create a module-level in-memory store: `getCsrfToken()`,
  `setCsrfToken(t)`, `clearCsrfToken()`. A module-level `let csrfToken: string |
  null = null`. NO localStorage (grep proof for PR body). SSR-safe: module
  state is per-tab/per-load by definition; it stays null until set.
- **VALIDATE**: `tsc --noEmit` clean; unit test asserts set→get→clear round-trip
  and that no `localStorage` symbol appears in the file.

## Task 2: Fetch interceptor cookie mode (`frontend/lib/authFetch.ts`)
- **ACTION**: At module top, `const COOKIE_AUTH = process.env
  .NEXT_PUBLIC_COOKIE_AUTH === 'true'`. In `installAdminAuthFetchInterceptor`,
  branch on `COOKIE_AUTH`:
  - **Cookie mode**: do NOT inject `Authorization`. Set `credentials: 'include'`
    on every request; for mutating methods (POST/PUT/PATCH/DELETE) on admin
    requests (`/api/v1/admin/`), attach `X-CSRF-Token` from `getCsrfToken()`.
    Keep single-flight `runRefresh()` + `notifyAuthExpired`/`notifyForbidden`.
    The 401-retry path stays: on 401, `runRefresh()` once, retry once.
  - **Bearer mode (flag off)**: the ENTIRE existing body runs unchanged
    (byte-identical) — regression guarantee (test 10).
  - **GOTCHA**: `credentials: 'include'` must be set on retries too (merge into
    the init spread, not the header build, so it isn't overwritten).
  - **GOTCHA**: CSRF header only on `/api/v1/admin/` mutations — NOT on
    `/auth/login`, `/auth/refresh`, `/auth/migrate-session`, `/auth/ws-ticket`
    (pre-auth or cookie-path-scoped). Reuse `isAdminApiRequest()` to scope.
- **VALIDATE**: `tsc --noEmit`; test 2 (CSRF on mutations, not GET); test 10
  (flag off = no credentials/CSRF).

## Task 3: AuthContext state machine + bootstrap + single-flight refresh
- **ACTION**: Refactor `AuthContext.tsx`:
  - Add `type AuthStatus = 'loading' | 'authenticated' | 'unauthenticated'`.
  - `isAuthenticated = status === 'authenticated'` (NOT `!!token`).
  - On mount (cookie mode): `GET /auth/me` (credentials: include). 200 →
    `setUser(data.user)`, `setCsrfToken(data.csrf_token)`, status =
    `authenticated`. 401 → `unauthenticated`. `isLoading=false` in finally.
  - `refreshAccessToken` (cookie mode): `POST /auth/refresh` with
    `credentials: 'include'` (NO Authorization header — refresh cookie sent
    automatically, scoped to `/api/v1/auth`). On 200: `setCsrfToken
    (data.csrf_token)`, return truthy sentinel (interceptor only needs to know
    refresh succeeded to retry — cookies carry the new access token). On !ok:
    return null.
  - Keep `setAuthRefreshHandler(refreshAccessToken)` — the interceptor's
    `runRefresh()` single-flights via `inflightRefresh`. **This IS the N3 fix**:
    concurrent 401s → exactly one `/auth/refresh` → no family-revoking race.
  - Bearer mode (flag off): keep ALL existing logic unchanged.
- **VALIDATE**: test 1 (bootstrap), test 3 (single-flight), test 8 (reload),
  test 9 (refresh fail → logout), test 10 (flag off unchanged).

## Task 4: One-time Bearer→cookie migration
- **ACTION**: In the mount effect (cookie mode), BEFORE `/auth/me` bootstrap,
  check `localStorage.getItem('auth_token')`. If present:
  1. `POST /auth/migrate-session` with `Authorization: Bearer <legacy_token>`
     (the ONE place a Bearer header is sent in cookie mode).
  2. On 200: `setCsrfToken(data.csrf_token)`, clear legacy keys
     (`auth_token`, `auth_refresh_token`, `auth_user`), then `/auth/me` bootstrap.
  3. On failure (401/409/429/network): clear legacy keys, status =
     `unauthenticated` (user re-logs in). No retry (rate-limited 5/60s).
  - **GOTCHA**: migration must `await` before `/auth/me` (cookies not set until
    migrate-session returns). Fine — `isLoading` is true during the mount effect.
- **VALIDATE**: test 4 (migration success), test 5 (migration failure).

## Task 5: Login / logout cookie wiring
- **ACTION**:
  - `login` (cookie mode): `POST /auth/login` with `credentials: 'include'`.
    On 200: `setUser(data.user)`, `setCsrfToken(data.csrf_token)`, status =
    `authenticated`. NO localStorage writes. NO `setToken`. Keep 5xx retry.
  - `logout` (cookie mode): `POST /auth/logout` (credentials: include,
    fire-and-forget). `clearCsrfToken()`, status = `unauthenticated`,
    `router.replace('/login')`. Broadcast `logout` (Task 7). Keep bearer-mode
    localStorage cleanup for flag-off.
  - Bearer mode (flag off): login/logout unchanged.
  - **GOTCHA**: login page calls `login()` from useAuth — no signature change.
    `dev_bypass` localStorage flag (login page line 433) stays for dev mode.
- **VALIDATE**: test 6 (logout); manual: login → reload stays authenticated.

## Task 6: WebSocket ticket auth
- **ACTION**: In `useWebSocket.ts` (or the live-chat hook calling it):
  - Cookie mode: before `client.connect()`, `POST /auth/ws-ticket` (credentials:
    include) → `{ticket}`. Pass `ticket` (not JWT) as the WS auth token. On
    reconnect, re-mint a fresh ticket (single-use).
  - `WebSocketClient` auth message shape stays the same; only the value
    changes JWT → ticket.
  - Bearer mode (flag off): send JWT as today.
  - **GOTCHA**: ws-ticket fetch can fail (401/429) — do NOT connect WS; stay
    disconnected (same as today when no token). Log a warning.
  - **GOTCHA**: ticket is single-use + short-lived (WS_TICKET_TTL). Reconnect
    after long disconnect must mint a NEW ticket. Wire ticket-mint into the
    connect effect, not a one-time ref.
- **VALIDATE**: manual smoke (live-chat in cookie mode); unit test for
  ticket-mint-before-connect (mock fetch).

## Task 7: Multi-tab sync (BroadcastChannel)
- **ACTION**: In AuthContext, `new BroadcastChannel('jsk:auth')` (guarded by
  `typeof BroadcastChannel !== 'undefined'`; fallback: `storage` event for
  sentinel key `jsk:auth-logout`). On logout/expired: `bc.postMessage
  ({type:'logout'})`. Listener: `clearCsrfToken()`, status = `unauthenticated`,
  `router.replace('/login')`. Clean up on unmount. Cookie mode only.
  - **GOTCHA**: no echo loop — BroadcastChannel doesn't deliver to sender tab;
    `storage` fallback fires in OTHER tabs only. Both safe.
- **VALIDATE**: test 7 (BroadcastChannel logout → listener unauthenticated).

## Testing Strategy
FR10's 10 cases are the unit/integration spec. Edge cases: expired ticket
reconnect, cookie present in bearer mode (ignored), CSRF header present but
token null (skip — let it 403), logout with no cookies (idempotent 204),
multiple tabs (BroadcastChannel), concurrent 401 burst (single-flight).
