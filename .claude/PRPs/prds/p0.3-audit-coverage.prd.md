## Problem

User creation/role changes, password resets, credential and integration writes,
permission-matrix changes, system-setting changes, media deletion, and broadcast
lifecycle actions leave **zero audit trail**. `AuditLog` model, `create_audit_log()`
helper, and the admin audit-viewer UI all exist — endpoints just never write records.

## Mechanism (binding)

Use the existing `create_audit_log(db, admin_id, action, resource_type, resource_id,
details)` helper (`backend/app/core/audit.py`) called **inside the endpoint, on the
same `db` session, before the endpoint's `commit()`** — so the audit row shares the
mutation transaction (rollback drops both; acceptance criterion "failed mutations
leave no audit entries" follows for free). Do NOT use the `@audit_action` decorator
for endpoints (its argument-sniffing is service-layer specific and fragile); do not
refactor it either — out of scope.

Action naming: `<verb>_<resource>` snake_case matching the existing live-chat style
(`claim_session`, `send_message`), e.g. `create_credential`, `reset_password`.

## FR2 — Redaction (hard requirement)

`details` must never contain: secrets, passwords (plain or hashed), tokens, encryption
material, full credential payloads, or webhook URLs with embedded secrets. Field
NAMES and coarse metadata only. Add one shared helper in `app/core/audit.py`
(e.g. `redact_changed_fields(payload: dict, allowed_keys: set) -> dict` or a
changed-field-names extractor) if it removes repetition — small and obvious only.

## FR3 — Tests: new `backend/tests/test_admin_audit_endpoints.py`

Mirror existing admin-endpoint test idioms (find how existing tests authenticate —
check `backend/tests/` for admin endpoint tests and copy their auth approach; if
none authenticate, use the same monkeypatch/dependency-override pattern the repo
already uses). Required cases:
1. One success-mutation test per file (6 minimum) asserting: exactly one new
   AuditLog row; `admin_id` == acting admin; `action`/`resource_type`/`resource_id`
   correct.
2. One failure case (e.g. update non-existent credential → 404) → zero new rows.
3. Redaction: credential create/update and reset_password audits contain no secret
   value (plant sentinel secret in request, assert absent from details JSON).
4. Transaction sharing: a mutation that fails AFTER the audit call but BEFORE commit
   (simulate via monkeypatched commit failure or an invalid follow-up write) leaves
   zero audit rows.
5. Existing audit list endpoint (`admin_audit.py`) returns the new entries with
   filters working (one smoke assertion).

## Non-Goals

- Auditing the remaining endpoint files (intents/auto-replies/canned/reply-objects/
  tags/rich-menus/requests) — follow-up after P0.3 lands; P0 checkpoint doesn't
  require them.
- Login/refresh auditing in auth.py (plan says "where appropriate" — deferred to
  P1.1 cookie-auth work where the auth flow is being rebuilt anyway).
- Refactoring `@audit_action` or live-chat audit paths.
- IP/user-agent capture (helper supports it; adding Request plumbing to 20+
  endpoints is noise — defer).

## Acceptance Criteria

- [ ] Full backend suite green (baseline 601 + new tests, 0 failures).
- [ ] Sentinel-secret redaction tests pass.
- [ ] Existing audit viewer endpoints/filters still green (existing tests +
      FR3 case 5).
- [ ] `git diff --check` clean; commit convention; no model IDs.

## Rollout note (PR body)

no flag needed. Audit writes add one INSERT per privileged mutation — negligible
