  participant R as HTTP route

ปัญหา

โมดูล Rich Menu ปัจจุบันเปิดเผยการทำงาน LINE จำนวนมาก ขณะที่ route ยังครอบครองเงื่อนไขก่อน sync, local upsert, commit, guard และการล้มเหลวบางส่วน

แนวทาง

ดูดซับพฤติกรรมวงจรชีวิตทั้งภายในและภายนอกเข้าโมดูลเดิม โดยเก็บ Postgres และ LINE เป็นอะแดปเตอร์ภายใน

Deletion test

อะแดปเตอร์ LINE มีความลึก แต่ถ้าลบ orchestration ใน route ความซับซ้อนของวงจรชีวิตจะกระจาย จึงควรทำโมดูลเดิมให้ลึกขึ้น

  • locality: รูปแบบความล้มเหลวอยู่ด้วยกัน
  • leverage: ใช้กับทุก route ที่แก้ข้อมูล
  • อินเทอร์เฟซวงจรชีวิตเล็กลง
  • ทดสอบที่ผลลัพธ์

แนวทาง

คงอะแดปเตอร์ transport ทั้งสองไว้ แต่รวมผลลัพธ์วงจรชีวิตหลังรอยต่อจริงที่ทั้งคู่ใช้อยู่แล้ว

Deletion test

ลบ orchestration ฝั่งใด ความซับซ้อนยังอยู่ในอีกฝั่ง การมี implementation ลึกชุดเดียวจะรวมความซับซ้อนไว้ได้

  • สองอะแดปเตอร์: รอยต่อจริง
  • locality: transaction + event
  • leverage ข้าม transport
  • พื้นผิวทดสอบเดียวกันสองทาง
