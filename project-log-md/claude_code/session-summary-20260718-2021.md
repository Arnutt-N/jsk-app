## Completed — broadcasts table PROD drift (PR #141, `27262f6`)

**Root cause**: the `Broadcast` ORM model (`app/models/broadcast.py`) has always
declared a `broadcasts` table (registered in `app/models/__init__.py`), but no
migration ever created it — a live-schema drift documented in
docs/remediation/preflight-evidence-and-designs.md §8. Probed both DBs: neither
local nor PROD had the table or its two enum types (clean slate on both).

**Migration `y0z1a2b3c4d5`** (down_revision `x9y0z1a2b3c4`, the head on both
local and PROD), hand-written:
- Creates enum types `broadcaststatus` (DRAFT/SCHEDULED/SENDING/COMPLETED/
  FAILED/CANCELLED) and `broadcasttype` (TEXT/IMAGE/FLEX/MULTI/OBJECT_REF),
  then the `broadcasts` table.
- **Enum labels are the uppercase Python member names**, not `.value` —
  SQLAlchemy's `Enum(PyEnumClass)` stores names by default (confirmed by the
  runtime query casting `'SCHEDULED'::broadcaststatus`). Wrong casing would
  make every insert/query fail with `invalid input value for enum`.
- Additive + idempotent: `upgrade()` no-ops if the table exists; enums created
  with `create_type=False` on columns + explicit `.create(conn,
  checkfirst=True)`; `downgrade()` guarded and reversible.
- Hand-written (not autogenerated) to avoid pulling in the sibling §8 drift
  (districts/provinces/sub_districts), same rationale as `w3x4y5z6a7b8`.

**Verification**:
- Local (docker PG16): upgrade creates table + both enums with correct labels;
  ORM insert applies Python defaults (enums, counts=0); the exact scheduler
  query (`status == SCHEDULED`) returns the row; downgrade -1 + re-upgrade
  cycle clean.
- CI on PR #141: all green (Backend Pytest, Frontend, Playwright, Encoding,

- **PROD applied** via `db_target.py alembic --target remote upgrade head`;
