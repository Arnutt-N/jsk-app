# P1 — Authentication, Authorization, and Durability

## P1.1 HttpOnly Cookie Authentication

### Files

- `backend/app/api/v1/endpoints/auth.py`
- `backend/app/api/deps.py`
- `backend/app/main.py`
- `frontend/contexts/AuthContext.tsx`
- `frontend/lib/authFetch.ts`
- `frontend/app/login/page.tsx`
- Backend auth tests, frontend auth unit tests, and `frontend/e2e/auth.spec.ts`

### Architecture

- Store access and refresh tokens in `HttpOnly` cookies.
- Use `Secure` in production.
- Use appropriate `SameSite` and path restrictions.
- Add a logout endpoint that clears all authentication cookies.
- Use a double-submit CSRF token for state-changing requests.
- During rollout, read cookies first and temporarily retain Bearer-token compatibility.
- Remove access and refresh tokens from browser `localStorage`.
- Use `credentials: "include"` for authenticated frontend requests.

### Acceptance Criteria

- JavaScript cannot read access or refresh tokens.
- Login, refresh, expiry, logout, and concurrent refresh behavior are tested.
- State-changing requests without a valid CSRF token are rejected.
- Existing sessions have a documented migration/expiry path.
